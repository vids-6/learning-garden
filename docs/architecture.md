# Architecture and durability

Single application module; package by responsibility and feature. Feature code depends on domain ports and models. AppContainer is the composition root and exposes domain interfaces. Android adapters live in data or in the feature that owns the platform interaction. Domain has no Android, Compose or Room imports.

`LearningRules` reduces a RunState and does not perform I/O. The repository checks the incoming state against Room inside a transaction before applying an answer. It inserts an immutable XP row and saves the updated session together. The UI enables another submission only after persistence completes. A maximum of two submissions is enforced by the reducer even if the UI sends duplicates. Match-pair mismatches count as submissions. Correct pairs are reconstructed through text after a restart; the durable activity boundary and attempt count are retained.

Next commits its advanced index before completion. If the process dies between those transactions, the lesson screen detects the end index and finishes safely. Completion reads the prior best, stores max stars and score, adds badges, logs the result and saves the complete RunState in one transaction. Repeating completion returns the stored result. XP row IDs use deterministic UUIDs from run/activity identity to prevent duplicate rewards. Completion XP is one row per run. Replays are new runs and can earn practice XP.

Every learner has one session. Home prompts before replacing a different unfinished lesson. Returning to the same lesson resumes it. Switching profiles never deletes another learner’s session. Best scores and completed lesson count survive all replays.

Settings are DataStore Preferences. AppCompat owns per-app locale persistence too, including Android 7–12. The locale is applied on startup after local settings arrive. No database work blocks rendering. Shared phones have no password-based isolation; the profile picker is a convenience.

The sync outbox is append-only until acknowledged. Each local research event is a UUID outbox trigger; transactional mutations also log events, so profile/progress/XP/badge changes enqueue a trigger atomically. A fake exchange sends a snapshot plus pending UUIDs. The worker re-reads local state inside its merge transaction after simulated latency, preventing stale remote progress from replacing new local progress. XP/event UUIDs, badge composite keys and practice-day keys are unions; stars, scores and attempts use maxima. Profiles use updatedAt. The fake's server memory is intentionally ephemeral; production sync is outside this prototype.

Analytics are local. The researcher task-completion denominator is distinct lesson run IDs started; numerator is corresponding runs completed. Time on task is average wall-clock duration of completed runs, including interruptions. Navigation errors count wrong_tap events (currently invalid matching taps). First/repeat quiz scores use the prior completed-attempt flag, not activity retries. Survey averages use 0=no, 1=somewhat, 2=yes. CSV follows RFC4180 quoting and neutralizes spreadsheet formula prefixes. Session_end is best effort when the Activity stops; Android does not guarantee callbacks on force-stop.
